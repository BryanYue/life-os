# 本地架构与边界

v0.1 使用单个 Fastify 进程提供生产静态资源与 API，React 按模块清单生成界面。Node 24 的内置 SQLite 避免 native addon 安装步骤；API 状态与笔记写入都是同步的，适合个人小规模数据，未做大数据性能承诺。生产资源按构建时已存在的文件白名单提供。服务不发出外部网络请求。

## 数据与职责

`entities` 保存实体的结构化当前状态；`edges` 保存有类型的有向关系；ID 不依赖显示名称与笔记路径。每个模块有多个实体类型，字段生成 JSON Schema 交由 AJV 校验。核心 API 版本、模块发布版本、Schema 版本独立。

计划、事实、推断是不可互改的身份。状态可为草稿、进行中、完成、失败；记录保存发生时间、原始时区、创建/修改时间、修改者、来源和递增版本。发生时间接受日期或明确偏移的 ISO 时间；规划的开始/结束分钟表示该日期在所选时区的本地墙钟时间，不将未知真实日程推断成事实。跨夏令时存在重复/缺失钟点时，本版没有自动消歧，应使用明确偏移的事实时间。

SQLite `audit` 仅保存对象、动作、版本、修改者和时间，不放私人正文。独立的 `operations` 与 `note_index` 是同步/恢复所需的私有历史，含正文快照，必须与数据库同等保护。本版没有历史过期清理或防篡改审计保证。

## Markdown 主版本

每个实体有带 `life_id`、`life_module` 的 Markdown 笔记。正文以文件为主；数据库只保留同步检查点和恢复日志。扫描稳定 ID 可识别笔记移动；未知 frontmatter 和正文保留。读取或编辑损坏/重复身份时返回可见错误；不执行笔记 HTML、脚本或指令。

编辑采用实体版本 + 笔记 hash 双检查，过期编辑返回 409。数据库事务先提交结构化状态、操作日志和 `pending_notes`；再用 fsync、临时文件与原子替换写入既有托管笔记。新笔记使用排他创建；同名非托管文件保留，应用改用不冲突的文件名。进程中断后重放待写日志。若文件已经被外部改动，拒绝覆盖，使用 CLI 恢复选择。**这是可恢复协议，不是跨数据库与文件系统的天然原子事务。**

导出同步、接收同步、备份和冲突检查会捕获外部 Markdown 改动并生成新操作。本版没有后台文件监视器；刷新界面读取当前正文，但同步变更在这些明确操作时入日志。符号链接与路径越界被拒绝；对拥有同一主机文件权限的恶意进程不提供沙箱。

## 权限与本机接口

浏览器从本地入口取得 HttpOnly / SameSite=Strict 会话，写请求还需随机 CSRF token。检查 Host、Origin、跨站 Fetch 元数据；默认仅回环绑定。API 无 CORS 开放，无外部执行、交易、支付或消息发送接口。

可选本机配置可授予独立 Agent token 和模块范围。携带 Agent 凭据的请求不能申请人工会话；无效凭据不会回退到浏览器会话。Agent 只能访问专用读取/建议端点，不能调用普通写入、备份或外部执行；建议只创建 draft inference。默认没有启用任何 Agent token，也不连接付费模型服务。本机 UI 以当前系统用户为操作者，**不声称识别恶意本机程序或隔离能读取本机配置的代理**。

插件目前是用户信任的声明式 JSON 模块。文件放在数据目录 `plugins/`，不会进入公开构建。任意代码插件、隔离进程和完整 capabilities runtime 是后续范围；不会声称进程内逻辑权限是恶意插件沙箱。

## 规划和领域

规划器先检查受保护块，再扣除用户填写的生活预留。剩余容量按普通、加班、疲劳系数及多个目标平均上限分配；缺口可见，不侵占受保护时段。草案无写入，采纳批量事务写入计划并以草案摘要保证重试幂等。此为可解释启发式规则，不是最优排程器；周期轮换、自定义情境、地点移动模型与跨日时区消歧尚待扩展。

财务收支使用最多八位小数的字符串及 BigInt 运算，分币种和分类汇总事实。资产负债快照与收支分开；汇率只记录来源和日期，未自动换算。量化只管理研究实验与结果记录，不执行回测或实盘交易。

## 可靠性限制

恢复在隔离临时目录中校验全部必需表、Schema、实体/笔记身份、正文索引、关系、历史引用与路径，再发布新目标目录；校验失败清理临时目录，不发布部分恢复数据，可修正备份后原路径重试。备份包含受管理实体的笔记、模块、操作、游标、去重和迁移状态，不包含仓库外未知附件或未注册笔记。数据目录权限限制为当前用户；CLI 支持可选 AES-256-GCM 认证加密导出，见 README；数据库/Vault/自动迁移备份仍是明文，没有 Keychain、设备密钥管理、自动备份或过期清理。

来源导入的 `(namespace, recordId, revision)` 与规范化内容摘要保留为修订收据。新来源默认实体 ID 由来源身份确定；同步接受来源操作时重建收据与当前修订，旧版本同步留下的缺失收据可从操作历史修复。普通人工编辑不会覆盖来源原始收据；同一修订携带不同内容被拒绝。同来源历史去重不以本机操作顺序推断来源版本大小。

文件与 SQLite 没有共同事务；备份先捕获外部笔记变更，再在数据库事务内读取逻辑表与对应笔记，正文和 note_index 不一致时拒绝备份并要求重试。本版支持个人单服务使用，不承诺防御同权限恶意进程或跨进程文件竞争的所有窗口。
