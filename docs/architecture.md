# 本地架构与边界

v0.1 使用单个 Fastify 进程提供生产静态资源与 API，React 按模块清单生成界面。Node 24 的内置 SQLite 避免 native addon 安装步骤；API 状态与笔记写入都是同步的，适合个人小规模数据，未做大数据性能承诺。生产资源按构建时已存在的文件白名单提供。核心不发出外部网络请求；显式信任的本地 stdio 插件无法获得完整网络隔离，见插件边界。

## 数据与职责

`entities` 保存实体的结构化当前状态；`edges` 保存有类型的有向关系；ID 不依赖显示名称与笔记路径。每个模块有多个实体类型，字段生成 JSON Schema 交由 AJV 校验。核心 API 版本、模块发布版本、Schema 版本独立。

分类 registry 只组织导航，与实体的 module/type 分离。个人 profile 是仓库外数据根中的私人文件，保存语言、排序、标签、模板和历史显示偏好；模块实际启停由 SQLite 唯一决定。GET 不初始化配置文件，不根据陈旧 profile 自动恢复插件授权。启停统一检查依赖和代码授权，Schema 迁移保持原启停状态。停用数据仍可历史读取；常规建议使用启用模块，启停不扩大同步权限。

任意语言使用规范化 code 作为身份、用户显示名作为展示；兼容旧中文字段，读取不重写。schema2继续有效，2→3显式扩大语言字段，保留未知字段与笔记。报告提供按code的权威分钟及兼容显示视图；相同显示名不合并不同语言。模板是无代码的声明数据，预览不写库，明确采用只生成计划，操作ID/请求摘要实现幂等，后续模板版本不改旧实例。

计划、事实、推断是不可互改的身份。状态可为草稿、进行中、完成、失败；记录保存发生时间、原始时区、创建/修改时间、修改者、来源和递增版本。发生时间接受日期或明确偏移的 ISO 时间；规划的开始/结束分钟表示该日期在所选时区的本地墙钟时间，不将未知真实日程推断成事实。周期规划逐日解析 IANA 时区：不存在的钟点拒绝；重复钟点要求用户在 offsets 中明确偏移。跨 DST 切换的窗口要求拆分，避免把墙钟分钟误当真实经过时间。事实使用明确偏移时间。

数据根、Vault、profile、模板、插件授权、`config.json` 和密钥文件都在仓库外。`outsideRepository` 先解析已存在祖先的物理路径再判断，同时拒绝本机其他 Life OS 源码 checkout（祖先同时含 `.git`、`package.json` 名 `life-os` 与 `src/paths.ts`；只有 `.git` 的私人笔记仓库不受影响），`Store` 构造、`Store.restore`、profile、密钥/导出、工作区保全与服务/CLI 入口共用它，拒绝发生在创建目录或改权限之前。发布扫描另行检查私有文件类型、凭据、备份载荷、邮箱/提交身份与个人机器路径；`.gitignore` 只防误加，不作为隔离证明。职责矩阵见[整合计划](tasks/local-v01/consolidation-plan.md)。

SQLite `audit` 仅保存对象、动作、版本、修改者和时间，不放私人正文。独立的 `operations` 与 `note_index` 是同步/恢复所需的私有历史，含正文快照，必须与数据库同等保护。本版没有历史过期清理或防篡改审计保证。

## Markdown 主版本

每个实体有带 `life_id`、`life_module` 的 Markdown 笔记。正文以文件为主；数据库只保留同步检查点和恢复日志。扫描稳定 ID 可识别笔记移动；未知 frontmatter 和正文保留。读取或编辑损坏/重复身份时返回可见错误；不执行笔记 HTML、脚本或指令。

编辑采用实体版本 + 笔记 hash 双检查，过期编辑返回 409。数据库事务先提交结构化状态、操作日志和 `pending_notes`；再用 fsync、临时文件与原子替换写入既有托管笔记。新笔记使用排他创建；同名非托管文件保留，应用改用不冲突的文件名。进程中断后重放待写日志。若文件已经被外部改动，拒绝覆盖，使用 CLI 恢复选择。**这是可恢复协议，不是跨数据库与文件系统的天然原子事务。**

导出同步、接收同步、备份和冲突检查会捕获外部 Markdown 改动并生成新操作。本版没有后台文件监视器；刷新界面读取当前正文，但同步变更在这些明确操作时入日志。符号链接与路径越界被拒绝；对拥有同一主机文件权限的恶意进程不提供沙箱。

## 权限与本机接口

浏览器从本地入口取得 HttpOnly / SameSite=Strict 会话，写请求还需随机 CSRF token。检查 Host、Origin、跨站 Fetch 元数据；默认仅回环绑定。API 无 CORS 开放，无外部执行、交易、支付或消息发送接口。

可选本机配置可授予独立 Agent token、模块范围及 `agentScope` 中的实体/类型/字段/正文/元数据权限。`config.json` 是服务授权的唯一文件，服务与 CLI 在打开 `Store` 前经 `loadLocalConfig` 严格读取：只接受 `agentToken`、`agentModules`、`agentScope`、`syncModules`、`syncScope`，scope 复用权限校验，拒绝符号链接、FIFO、目录与超过 256 KB 的文件，错误不回显值；拼错的键不再被静默忽略成整模块访问。`config init` 只显式生成新的 0600 空授权文件、不覆盖，`config show` 脱敏令牌；修改后需重启服务，不做热加载。读取按同一核心规则投影，搜索只针对获准用户数据，隐藏字段与 noteHash 不经读取或同步旁路泄露。字段写入检查差异，`patchFields` 保留不可见字段、正文、来源与关系，并检查版本；不能修改或移除不可见关联。携带 Agent 凭据的请求不能申请人工会话；无效凭据不会回退到浏览器会话。Agent 只能访问专用读取/建议端点，不能调用普通写入、备份或外部执行；建议只创建 draft inference。默认没有启用任何 Agent token，也不连接付费模型服务。本机 UI 以当前系统用户为操作者，**不声称识别恶意本机程序或隔离能读取本机配置的代理**。

声明式模块与完整插件共享 Module 契约。插件增加操作、权限、导入器、依赖、版本兼容和迁移；安装路径必须在仓库外。read/suggest 默认可授权，write 单独选择，external broker 永拒绝。安装、授权、启用、停用、升级、卸载分别持久化，升级撤销旧授权；卸载保留业务数据。

可信单文件 stdio 插件在 Node 24 permission 子进程中运行，限制文件、子进程、worker、addon，限制时长/输出且清除继承环境；通过 broker 读取或暂存写入，成功后再次检查授权并事务提交。需要明确认可本地代码及网络未隔离两个选项；代码 hash 改变即拒绝。Node permission 不是恶意代码沙箱，也不能阻止已信任代码自行联网。无真正 OS 网络隔离前，不支持不可信插件。安装路径/执行配置/信任授权存仓库外 plugin-state.json，不进入数据备份；恢复停用可执行插件。详见 modules.md。

## 规划和领域

规划器先检查受保护块，再扣除用户填写的生活预留。剩余容量按普通、加班、疲劳系数及多个目标平均上限分配；缺口可见，不侵占受保护时段。草案无写入，采纳批量事务写入计划并以草案摘要保证重试幂等。周期规划按用户提供的连续日期、窗口、容量系数轮换多个低强度目标；已有领域目标通过 supports 关联。地点转移只使用明确提供的路程分钟，未知路程给出缺口；不猜测通勤或用户作息。周期复盘依据唯一 actual-of 事实和证据产生建议，多目标归属歧义不重复计入。这是可解释启发式规则，不承诺最优排程。

财务输入为最多八位小数的字符串，使用 BigInt 精确相加/相减/相乘，换算结果保留实际精度。报告分币种与分类，资产负债按账户最新快照重建 UTC 历史。只使用发生日期/报价日期不晚于估值时点的显式直接汇率，并返回来源；缺汇率返回不完整和部分合计，不把部分数值当完整净资产。

健康趋势分离单位与主观/设备来源；计划对照保留所有实际状态并分别计算已完成，歧义 actual-of 不重复计入。Apple XML 手动适配由 saxes 解析，限制大小/记录数/DTD，不加载外部实体，解析或语义错误不会写入有效前缀。步数、心率、Workout 时长有单位/时区/修订校验；只验证合成文件，不代表 HealthKit 授权。

研究结果通过 life-os-research-v1 导入，明确 not-run/failed/succeeded，提案是计划而运行结果是事实；保留数据/代码/参数/费用/滑点/评价来源用于比较。结果记录不是应用执行过回测的证明，也不连接真实仓库或实盘。学习、项目、语言、家庭通过稳定关系复盘形成各自记录链。

综合阅读使用单一 `learning/session` 事实计时，支持多个目标和语言视角；不同视角不可相加成总时间。材料正文不被解释或词汇覆盖，解释为独立 inference。清单计划的完成/撤销与事实打卡批量提交，提醒只在本地页面读取时分类到期，不注册系统通知或后台任务。规则建议提供规则版本、理由与证据，读取不写库，人工采纳只建立计划；没有记录不推定用户失败。

表达原稿与整理稿分开保存，可选观点/理由/证据结构，无固定句数。反馈只检查结构覆盖与来源可用性，不证明主张真实；整理建议须人工采用。结构中的实体证据也写成关系，沿用同步范围检查。所有业务命令有稳定操作 ID，成功后的重试核对原请求并返回当前记录，不因目标后来完成而重复写入或回退修改。日期时间选择器显式使用 IANA 时区，夏令时缺失钟点拒绝、重复钟点要求选择偏移。

## 可靠性限制

恢复在隔离临时目录中校验全部必需表、Schema、实体/笔记身份、正文索引、关系、历史引用与路径，再发布新目标目录；校验失败清理临时目录，不发布部分恢复数据，可修正备份后原路径重试。备份包含受管理实体的笔记、模块、操作、游标、去重和迁移状态，不包含仓库外未知附件或未注册笔记。同步协议有当前 Schema 初始化、增量操作及独立只读字段投影；前两者只接受完整可编辑记录范围。继承的去重收据支持三副本初始化，恢复校验收据和投影结构；仅本地手动模拟。数据目录权限限制为当前用户；CLI 支持可选 AES-256-GCM 认证加密导出，见 README；数据库/Vault/自动迁移备份仍是明文，没有 Keychain、设备密钥管理、自动备份或过期清理。

来源导入的 `(namespace, recordId, revision)` 与规范化内容摘要保留为修订收据。新来源默认实体 ID 由来源身份确定；同步接受来源操作时重建收据与当前修订，旧版本同步留下的缺失收据可从操作历史修复。普通人工编辑不会覆盖来源原始收据；同一修订携带不同内容被拒绝。同来源历史去重不以本机操作顺序推断来源版本大小。

文件与 SQLite 没有共同事务；备份先捕获外部笔记变更，再在数据库事务内读取逻辑表与对应笔记，正文和 note_index 不一致时拒绝备份并要求重试。本版支持个人单服务使用，不承诺防御同权限恶意进程或跨进程文件竞争的所有窗口。


## Obsidian 手动互操作与路径别名

Life OS 的独立运行不取消 Obsidian 互操作：SQLite 保存实体字段/关系/版本，仓库外专用 Vault 的 Markdown 是正文。设置页只展示已运行服务的 Vault 路径；人类会话 GET `/api/obsidian/vault` 返回路径与 `obsidian://choose-vault`，GET `/api/obsidian/notes/:id` 仅从受管理 ID 解析当前文件，拒绝删除/缺失/重复/身份变更/符号链接。路径和 URI 不向 Agent 入口或受限能力暴露；不接受任意文件路径，不启动 shell，不写 Obsidian 配置，也不读其他 Vault。

用户先在同机 Obsidian 注册此文件夹，再显式点击已保存笔记的 `open?path=` URI；值按官方 [URI 文档](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI) 百分号编码。API 不保证安装或注册成功，跨设备浏览器不能用服务器路径打开本地笔记。外部编辑需在页面刷新后重新打开，已有版本/正文 hash 校验阻止旧表单覆盖；冲突保留与 `recover-note` 流程不变。没有后台 watcher、嵌入或自动同步。

Mac `/var` 临时目录别名导致 Node24 permission 入口加载失败；plugin runner 在 mkdtemp 后使用 realpath，再以同一物理路径设置 cwd、entry 与单文件 `--allow-fs-read`。权限没有扩大，子进程/worker/其他文件仍拒绝；可信 stdio 网络未隔离的已有边界不变。
