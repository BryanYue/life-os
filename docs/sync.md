# 本地双副本同步模拟

这里只验证本地协议，不是自动云同步。没有供应商、账号、存储费用、真实同步范围或设备授权；程序不会上传数据，也不会用网盘覆盖运行中的 SQLite。

## 明确启用模拟范围

默认导出空范围。两个独立数据目录各自可放本机 `config.json`，例如仅虚构规划与学习记录：

```json
{ "syncModules": ["planning", "learning"] }
```

这是本地演练的模块白名单。`family` 无论配置如何都拒绝同步。实体/字段级白名单、网络传输、Keychain、撤销和正式云端授权适配器尚未实现。CLI 可用可选认证加密信封保护手动交换文件；**加密不会授权云服务或扩大同步范围**。浏览器和普通命令仍输出明文。

```bash
LIFE_OS_HOME=/tmp/life-a npm run cli -- export-sync /tmp/a-batch.json 0
LIFE_OS_HOME=/tmp/life-b npm run cli -- import-sync /tmp/a-batch.json
```

导入结果返回 `cursor`；下一次导出使用这个游标，文件名需为新路径。导出每包最多 500 条日志跨度；即使白名单过滤后没有操作，也用包的 `to` 推进对应源设备游标。新增授权模块需要从游标 0 重放历史以补齐记录。跨模块关系的目标必须已在接收端存在且获准，否则整个包拒绝，不能静默删掉关系。

## 包与事务

包包含协议版本、设备/批次标识、起止游标、完成标志、操作 ID、操作源序列、基础快照、新快照和 SHA-256 摘要。摘要只检测意外损坏，**不是认证签名或防恶意篡改**。不认识的版本、未完成包、游标缺口、权限或 Schema 错误拒绝处理。导入变更、冲突、游标在同一 SQLite 事务提交，文件投影随后通过可恢复日志应用。

操作 ID 去重；重复投递不增加副本，同 ID 携带不同内容会拒绝。接收来源导入操作也重建来源修订收据；接收端再导入同修订不会重复，新修订更新同一稳定实体。导出和导入均校验当前及历史基础快照的关系目标模块，跨出白名单时整包拒绝，不通过关联泄露被排除模块的 ID。断网继续本机读写，手动重新导出/导入可补齐；没有后台轮询、网络重连服务或自动发现对端。

## 冲突与恢复

结构化字段基于共同基础快照三方比较；互不冲突的字段合并，同字段竞争保留双方。Markdown 使用 node-diff3 三方合并；相同位置冲突保留在数据库冲突队列。设置页可审阅正文和字段，选择本地或传入版本。选择本身生成新操作并标记已解决的竞争操作，使两端后续交换可以收敛；更新的竞争修改仍需单独审阅。

删除是可恢复 tombstone，同步不会简单复活离线删除的实体。AI 推断、事实、计划以及模块/类型身份不能通过合并改换。同步日志和冲突副本含完整私人内容，不属于可公开审计日志。

备份包含数据库逻辑表、受管理 Markdown、模块/迁移版本、操作与游标、来源去重记录。恢复到新目录后赋予新设备 ID 并标记隔离，不自动上传。实际测试覆盖恢复、旧包重放、停用模块恢复、崩溃后文件日志重放及外部编辑冲突选择。恢复先在临时目录验证，成功后发布新目录；路径、正文索引、关联不一致或缺表备份被拒绝，不留下可用的部分恢复目录。附件二进制、周期备份和真实服务端联动仍是剩余范围。

## 可选本机加密信封

先按 README 创建仓库外密钥并设置 `LIFE_OS_KEY_FILE`，再使用 `export-sync-encrypted FILE [CURSOR]` 与 `import-sync-encrypted FILE`。双方在本地演练中需持有相同密钥；本程序不传输或分发密钥。信封用随机 96 位 nonce、256 位密钥和 128 位认证 tag 的 AES-256-GCM，固定版本/用途作为附加认证数据。错误密钥、篡改、错误用途和未知版本在导入前拒绝；包内原有模块授权、去重、游标及冲突检查继续执行。实现使用 [Node.js 原生 crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html)，没有自定义加密算法。

## 已知迁移重放限制

**部分实现：** 同一日志含 Schema 1 与 Schema 2 操作时，空副本无法只靠增量包完成跨版本初始化；该包拒绝且不推进游标或留下部分实体。尚缺带版本的迁移协商和按范围生成基线快照。已验证的本地恢复替代路径是用可信的完整备份初始化隔离副本，再重放已存在的操作；完整备份含所有模块，**不能作为较窄模块授权的同步包**。不批准真实数据跨端复制，也不把恢复测试称为迁移同步完成。
